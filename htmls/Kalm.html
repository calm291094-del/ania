Configura tu túnel WISP

  1. Consigue o despliega un servidor WISP (por ejemplo Epsilon o wisp-js).
  2. Pega su dirección WebSocket aquí (usa wss:// si alojas Kalm en GitHub Pages).
  3. Guarda y navega: el tráfico viaja dentro del túnel, como un archivo estático más.

Kalm funciona como página estática: para el firewall solo cargas un HTML; las peticiones salen por el túnel WebSocket.

Ajustes

Debe hablar el protocolo WISP (Epsilon, wisp-js, RubyVISP…). Si alojas Kalm en HTTPS (GitHub Pages) usa wss://; con ws:// el navegador lo bloqueará por contenido mixto.

Cómo funciona Kalm · despliegue · limitaciones
Cómo funciona: Kalm es un único archivo estático. Al navegar, abre un túnel WebSocket a tu servidor WISP y habla HTTP/1.1 dentro de ese túnel. El HTML/CSS que recibe se reescribe (imágenes, CSS, scripts → blob URLs) y se pinta en un iframe sandbox. Para la red, solo cargas una página de GitHub Pages: no hay Service Worker ni rutas de proxy.
Despliegue: sube Kalm.html a un repositorio público y activa Settings → Pages → main /root. Tu proxy quedará en https://tuusuario.github.io/tu-repo/.
Servidores WISP compatibles: Epsilon (Rust), @mercuryworkshop/wisp-js (npm, incluye CLI: npx wisp-js-server), RubyVISP, o cualquiera compatible con WISP v1.
Descargas: todo lo que descargues se empaqueta automáticamente como ZIP secuencial (00001.zip, 00002.zip…). El nombre original queda dentro del ZIP y en el panel de descargas.
Limitaciones honestas: el túnel solo puede hablar HTTP en claro: los sitios https:// no se pueden renderizar dentro del túnel (se ofrece modo directo/pestaña nueva). Los formularios con subida de archivos no están soportados; sitios con mucho JavaScript dinámico pueden fallar; los archivos enormes se procesan en memoria.
Uso responsable: el volumen de datos sigue pasando por tu red y queda registrado en sus logs. Respeta las políticas de tu institución: el uso de esta herramienta es responsabilidad tuya.
